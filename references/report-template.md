# 报告模板与措辞规范

## HTML 版式规范（主交付格式，2026-11-02 起）

交付单个自包含 HTML，双击离线可开。结构自上而下：

1. **页头**：彩期标题 + 生成时间/信息截止/覆盖场次/薄弱场次（meta 行，小字）
2. **横向速览表**：11 列以内，一行一场（编号/对阵/最该盯的变量）
3. **比赛卡 × N**：每场一张卡
   - 卡头：竞彩编号徽章 + 联赛 + 对阵 + 开球时间
   - 卡体：两队左右分栏（窄屏自动纵排），每队五板块 ①→⑤
   - 卡脚：本场关键影响因素速览（bullet）
4. **页脚**：免责声明 + 单源复核提醒 + **验证记录区块**

CSS 硬要求：

- 深色科技风：底 `#0b0f14`、卡 `#131a22`、边 `#1f2a36`、主文字 `#e6edf3`、
  次要 `#8b98a5`；强调色：主队 `#4ea1ff`、客队 `#f7b955`
- 内联 CSS，零外部依赖（无 CDN 字体/JS/图床）
- 徽章语义色：确定缺席 `#e5534b`、出战成疑 `#d29922`、复出/回归 `#3fb950`、
  停赛 `#a371f7`；信源等级用灰色小 tag（如「官宣」「单源」「主流多源」）
- 中文字体栈：`-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`
- 每板块 1–3 条 bullet，单卡 ≤ 45 行内容量，整体可扫读
- 板块标题带 ①–⑤ 序号，与 md 模板的五板块一一对应

## 合刊文件头（必写）

```markdown
# 竞彩球队简报 · YYYY-MM-DD（周X）彩期

- 生成时间：YYYY-MM-DD HH:MM（北京时间）
- 信息截止：各条目自带时点，整体以生成时间为准
- 覆盖场次：N 场（列出竞彩编号范围）
- 信息薄弱场次：无 / 周六00X、周六00Y（搜索颗粒不足，已如实标注）
```

## 单场模板

```markdown
## 周六001 西甲 · 皇家马德里 vs 巴塞罗那（开球 11-03 03:45）

### 皇家马德里

**① 近期新闻热点与舆论动向**
- 皇马官方确认维尼修斯肌肉不适，缺席合练（10/31，俱乐部官网）
- 西媒多源报道：中场线冬季引援计划提上日程（10/30，马卡/AS 均有报道，信源等级：主流媒体多源）
- （传闻层级内容必须带「据传/据报道」并标信源等级）

**② 近期竞技状态及战绩影响**
- 近 5 场：4胜1平，进 12 失 3。走势判读一句话：赢的三支中下游球队均零封，
  但对手强度有限，唯一强强对话 2-2 巴萨暴露由守转攻回追问题
- 战线取舍：周中国王杯大面积轮换，联赛主力蓄势迹象明显

**③ 球队内部问题**
- 伤病：库尔图瓦（膝伤，10/28 官宣，预计缺席 2 周）、阿拉巴（恢复性训练，出战成疑）
- 更衣室/其他：未检索到公开信息

**④ 关键球员首发与缺席**
- 确定缺席：库尔图瓦（10/28 官宣）
- 出战成疑：阿拉巴（10/31 训练名单外）
- 预计首发关键点：卢宁顶替门将位置；贝林厄姆位置回撤趋势近两轮明显（预测首发，非官宣）

**⑤ 教练执教风格与潜在战术问题**
- 主帅：哈维·阿隆索。风格标签：高位控球 + 边后腰出球，客场倾向收半档
- 本场潜在战术矛盾：对方高位逼抢强度 vs 皇马后场出球若缺阿拉巴的左路推进，
  出球线路可能被压缩半边（预测性判读，基于近期比赛观察）

### 巴塞罗那
（同结构，五板块齐全）

### 本场关键影响因素速览
- 皇马门将位置换人后的门线质量（官宣缺阵，影响确定）
- 巴萨周中多踢一场欧冠，体能储备差一个比赛日（赛程事实）
- 双方均无保级/出线压力，联赛动机对等
- （只列变量，不写「看好谁」，不给方向）
```

## 措辞规范（红线）

| 不写 | 写 |
|---|---|
| 「罗德里伤缺」（无时点） | 「罗德里伤缺（10/28 官宣）」 |
| 「皇马铁定取胜」 | 不写。方向判断不属于本技能 |
| 「曝出更衣室内讧」（单源） | 「据 XX 单源报道，更衣室出现分歧传闻（信源等级：单源小报）」 |
| 「哈兰德首发出战」 | 「哈兰德预计首发（预测，非官宣）」 |
| 「状态火热」堆砌 | 「近 5 场 4 胜，场均 xG 2.1，但对手均为后六名——数据好看含成色问题」 |

**三句占位语（空板块专用，统一措辞）：**
- 「未检索到公开信息」—— 搜了但没结果
- 「无公开报道的内部问题」—— 搜过且近期确无相关新闻
- 「风格样本不足」—— 新帅/新援场景

## 篇幅控制

- 每队每个板块 1–3 条 bullet，**全场报告 ≤ 60 行**
- 板块②③④允许各占 3 条，①⑤ 通常 1–2 条足够
- 「速览」3–5 条，每条 ≤ 30 字
- 超写压是信号：说明信息没做凝练，删形容词留事实

## 验证记录区块（每期必含，页脚前）

报告末尾必须有该区块，没有验证闭环的简报只是作文：

```markdown
## 验证记录

### 本期待回填（YYYY-MM-DD 彩期）
- 待验证「预计首发/确定缺席」：N 条（开球前 1h 官宣首发对照）
- 待验证盘口背离提示：N 条（与 jc-odds-baseline 赔率快照对照）
- 回填期限：下一彩期生成前

### 上期回填（YYYY-MM-DD 彩期，若存在）
- 「预计首发」命中率：X/N（错例：周六00X —— 简报判 A 伤缺，实际首发，信源为单源小报）
- 错误模式归纳：本错主要出在 L3 转述层 → 下期该类信息一律溯源 L1/L2
```

回填规则：

- 同队距上期 ≤ 7 天再跑时，**先回填上期验证记录，再出新一期**
- 错例必须归因到信源等级（L1/L2/L3/单源），归纳成一条可执行的改进
- 命中率连续 2 期 < 60% 时，报告头加显著提示「本技能该联赛信息颗粒不足」

## 坏示例（对照）

❌ 「皇马近期状态出色，攻击火力凶猛，主场作战能力强大，本轮有望延续连胜势头。」
—— 全是形容词，零事实零时点，还有方向倾向。

✅ 「近 5 场 4 胜 1 平（10/19–11/01），主场 3 连胜且每场净胜 2 球以上；
但对手均为积分榜下半区，唯一强强对话（10/26 vs 巴萨 2-2）平局收场。」
—— 有窗口、有数据、有对手强度校准，无方向。
